# Smart Attendance UI Kit

Build a frontend UI that matches the current Smart Attendance design as closely as possible.

This is a FRONTEND-ONLY project. Do not create backend code, APIs, database logic, authentication, ML, Python scripts, or real attendance logic. Use mock data only and keep everything visual.

Goal:

- Match the existing project’s design language closely

- Preserve the same layout composition and structure as the current app

- Follow the current visual hierarchy, button placement, spacing, and card styling

- Keep the same dashboard feel, professional academic branding, and modern UI style

Important: Make the design visually match the existing app structure, not just a generic attendance app.

Use the current app as the visual reference:

- Sidebar navigation with buttons on the left

- Dashboard cards with metric summaries

- Tables with clear rows and actions

- Clean card-based sections

- Buttons styled consistently across the interface

- Professional academic dashboard color palette

- Modern rounded cards and soft shadow styling

- Similar spacing rhythm between headings, cards, and sections

- Responsive layout for desktop/tablet/mobile

Include these screens:

1. Landing page

2. Login page

3. Signup page

4. Admin dashboard

5. Faculty dashboard

6. Student dashboard

7. Attendance management page

8. Class management page

9. Student records page

10. Analytics and reports page

11. Profile/settings page

UI matching requirements:

- Match the current design pattern of buttons, cards, panels, and sidebars

- Keep similar button sizes, shapes, label styling, and placement

- Use similar spacing between sections and same general page visual density

- Keep dashboard widgets aligned like the existing app

- Use a consistent premium educational management aesthetic

- Make forms, filters, and tables look clean and structured

- Keep design polished, balanced, and not cluttered

Do not include:

- backend or server code

- real auth or database logic

- ML or face recognition implementation

- real QR validation

- API integration logic

The end result should feel like the current app’s design style, but rebuilt as a clean, premium frontend prototype with realistic mock data and matching structure.
